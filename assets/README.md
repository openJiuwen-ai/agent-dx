# Agent DX assets

This directory is the source of truth for reusable Agent DX brand and architecture assets.

## Structure

- `logo/agent-dx-lockup.png` — canonical white-on-black horizontal lockup for repository and documentation headers.
- `logo/agent-dx-lockup-black.png` — black lockup on a transparent field for controlled light surfaces.
- `architecture/agent-dx.svg` — product and platform system architecture.
- `architecture/current-architecture.svg` — repository component boundaries and current call paths.

## Design language

The Agent DX identity uses a small number of continuous geometric strokes. Rounded caps make the mark approachable without making it decorative, while the constant line weight reflects predictable infrastructure and stable contracts.

The symbol combines three letters and three platform ideas:

- **A — Agent.** The open left stroke is an entrypoint for agents, applications, and developer tools.
- **D — Distributed.** The rounded middle path connects access to multiple execution paths, representing placement across worker nodes under one execution contract.
- **X — eXecution.** The crossing right strokes represent dispatch and the meeting of control and data paths.

The opening in the mark is intentional. Agent DX provides access to isolated execution without visually sealing the system into a closed box. Negative space carries as much meaning as the visible stroke, so the mark should remain uncluttered and must not be combined with node dots, clouds, robot heads, shields, or circuit patterns.

## Usage

- Use only black and white. Do not add gradients, shadows, outlines, or accent colors.
- Keep a clear-space margin of at least one stroke width around the mark.
- Do not stretch, rotate, crop, recolor, or rearrange the letterforms.
- Use the lockup at 160 px wide or larger and preserve its aspect ratio.
- Prefer the canonical white-on-black file for uncontrolled surfaces such as repository renderers. Use the transparent black file only when the surrounding surface is known to be light.

Architecture diagrams use their own semantic colors to distinguish control, data, and support flows. Those colors are explanatory and are not part of the monochrome brand mark.
