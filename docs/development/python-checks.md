# Python 提交前检查

从仓库根目录运行，先安装 `uv`，并更新 PR 目标分支对应的本地 remote ref。例如目标分支为 `github/master`：

```sh
git fetch github master
make python-check PYTHON_CHECK_BASE=github/master
```

入口固定使用 Ruff 0.11.13 和 Pylint 3.3.8，首次运行由 `uv tool run` 安装工具。
它从目标分支与 HEAD 的共同祖先开始，检查 PR 中所有新增或修改的 Python 文件，
同时包含暂存、未暂存和未被忽略的新文件。扫描完整文件；删除的文件不扫描。
基线必须显式提供，无法解析时检查失败，避免漏掉之前提交里的文件。

当前本地规则覆盖：120 字符行宽、语法和常见名称错误、函数/参数/局部变量命名、
外层变量遮蔽、循环闭包的延迟绑定、重复及父子类重叠异常、直接使用 `print`，以及直接用相对命令名启动子进程。
规则配置在 `build/ci/ruff-codecheck.toml`，Pylint 规则与版本在 `build/ci/python-check.sh`。
该入口是独立本地预检，现有 Buildkite 流水线尚未调用它。

静态检查通过后，还要运行改动组件的回归测试。测试通过只能证明已覆盖的行为；
CodeCheck 的平台规则另行检查。处理 Python 代码时尤其注意：

- 类型校验使用 `isinstance`，字典分隔符保留空格；新增或修改的条件语句最多包含 3 个布尔表达式。
- 嵌套函数或类定义前保留一个空行；平台会检查本地默认规则未启用的 E306。
- 跨模块测试调用明确的公共校验入口，避免访问其他模块的下划线成员；平台会检查受保护成员访问。
  例如通过 `Commands.get()` 验证能力查询失败及重试，通过请求记录验证路由，不读取内部标志；
  HTTP 测试在客户端获取入口注入 MockTransport，不替换实例的 `_http` 字段。
- 导入与 Python 内置名称同名的 SDK 异常时使用别名，例如 `EnvironmentError as SDKEnvironmentError`，
  避免触发 `redefined-builtin`；不要为通过检查而改动公共异常类型。
- URL 使用 `urllib.parse` 构建和编码，CIDR 使用 `ipaddress` 构造；动态字典查找显式处理键缺失。
- 运行日志使用 `logging`；循环内定义的回调通过参数显式绑定循环变量，避免延迟绑定。
- 文件描述符通过上下文管理器配对申请和释放，正常及异常路径都必须关闭；`os.open` 显式传入权限参数。
  只读打开时权限参数不改变现有文件的权限；私有文件仍须独立验证属主、权限、类型和读取上限。
- CLI 若输出机器读取的 JSON，使用 `logging` 时应显式保留原来的输出流和无前缀格式。
- 筛选 Cargo 等外部工具的 JSON 记录时，复杂的多条件推导式改用显式循环；保留缺失和重复结果的拒绝逻辑。
- 推导式及生成器的筛选条件跨行、包含多重筛选或嵌套窗口统计时，拆成普通循环；本地预检不等同于平台的 G.EXP.04。
- CLI 准入单测可以拦截公开的 `ArgumentParser.error`，断言完整错误消息和后续执行入口未被调用；
  另用隔离CLI进程验证退出码2，保留错误参数确实拒绝的覆盖，避免平台将 `assertRaises(SystemExit)`误报为内部退出。
- 实例属性在 `__init__` 中声明；测试需要扩展 `sys.path` 时追加路径，避免插到首位覆盖既有模块。
- 外部命令先通过 `shutil.which` 查找、处理缺失，再解析为绝对路径。
- 第三方回调命名等例外需核对平台支持情况；本地 `pylint: disable` 不代表平台认可。
  测试 HTTP 接收器优先使用标准库 WSGI 函数回调；平台仍会检查 `do_POST` 等方法名，
  即使本地 Ruff 通过 `noqa` 放行，也不能视为平台命名检查已通过。
- 每次修复后重新检查整个 PR 的 Python 文件，避免改名等修复引入超长行。
- 推送后核对 CodeCheck 报告的 `head_sha` 与 PR 最新提交完全相同，并确认最终结果。

本地检查仅覆盖上述规则，不能等同于完整的远端 CodeCheck。后续平台发现的新规则，
应在修复时同步补入可自动检查的本地规则，或补入有明确适用场景的审查要求。
