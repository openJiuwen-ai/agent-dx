## 怎样理解性能结果

固定工作负载为1GiB单文件、单读者、1024×1MiB加EOF，应用缓冲4096B对齐。A为真实产品buffered文件源、256个4MiB对象，B应用O_DIRECT；A/B各2vCPU/4GiB，同宿主VM，mTLS、一FUSE线程/worker，无预取、B磁盘缓存或新增并行。准备写入/fsync、输出预分配/预触页及内容oracle在主计时外；不声称冷介质或独占宿主。

主计时从应用open开始，到所有数据read、EOF及close系统调用返回。FUSE RELEASE可能异步，新增关闭Meta和对A通知单独记录并确认完成；不能把这些范围机械加到墙钟上，也不能隐去该成本。

1. CRC去重的历史同批中位：2291.848→2120.338ms。
2. open授权的历史同批中位：2121.563→2023.811ms；三组配对下降中位3.72%。整体语义仍有下述未通过边界。
3. 三模式初测曾出现33.52%下降，但基线不稳定；后续固定二进制复测基线为3366.274/3198.575/4148.572ms，未复现旧2.024秒。两批保留为机制及问题记录，不认领为确定收益。
4. 最新default-off二进制没有性能运行。不得将旧模式样本重标为新二进制成绩，也不将历史中位数跨批相减作为可追回成本。

各批正文均交付1GiB、1024个数据RPC、16384帧；A/B显式复制各1GiB。关闭CRC没有同时去掉scratch复制、放大磁盘读粒度、池化缓冲或开启预取。

## 历史评审问题（本轮决策与待验收边界见新入口）

- 默认off可能成功交付正文静默损坏。写入保存CRC不代表读取时会检测损坏；因此不能依靠被跳过的CRC触发坏副本处理。
- receiver使用写时可信段表。当前A/B配置必须一致，不能宣称只修改B便可独立开启；无模式元数据按旧both解释，off服务端明确拒绝，不静默降级。
- receiver非对齐片段继续走A覆盖段及精确范围校验回退；不宣称所有读取都已只有B一遍CRC。
- 预取/缓存/共享owner接入尚未验收，不能把off数据标记为已校验，也不能无意重新引入默认正文扫描。
- 新读完成标记只用于读，不是存储对象或副本ACK的摘要算法；旧格式、混合版本、滚动升级未准入。
- 早期候选曾出现截短后新open使旧fd尾读在进入FUSE前返回EOF；历史失败保留。后续固定句柄以FOPEN_DIRECT_IO完成旧fd read/pread/EOF验证，fstat/mmap逐fd快照仍不保证，见后续交付。
- GC长运行曾因只枚举已轮转WAL导致全节点清单采集失败；目标旧对象直接检查另行通过，两者均保留，不能把整个样本写成全绿。
- 新持久GC上下文字段改变存储schema；只在全新隔离store和同版本Meta/A/B上验收。旧store迁移没有成绩。
- R1损坏测试只证明both/receiver返回EIO、off精确交付坏字节；未证明真实多副本隔离、恢复或自愈。
- 原PR93已有副本写测试返回DataLoss而断言预期InvalidArgument，失败和exit101保持，不改写路径或测试来掩盖。
