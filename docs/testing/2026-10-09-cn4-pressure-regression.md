# cn-north-4 SDK 压力回归

2026-10-09，在 `cn-north-4` 集群的 `akernel` 命名空间复跑历史 SDK 压力负载。本文记录本次执行证据，不替代正式发行包验收。

## 环境与比较边界

- 4 个 runsc 节点；同一客户端 Pod 串行执行 7 个压力阶段，避免各组互相干扰。
- 独立 API Server 测试入口使用修复版镜像 `sha256:764138bb124494c28c00afc4802fbd8fd70edffedc637f3fa8fab3565fcffc83`，二进制 SHA256 为 `49728e40d73a57eff9a6739b36e5f5297076be563331776ca838aa2ff3cb555c`。配置 `cache_entries=10000`，完成缓存及未知创建窗口均为 600 秒。
- 节点沿用前轮已验证的 Execd 镜像 `sha256:4f98767a85fc9607373397d7c588d30749dc6453824887fe943f585fb0a22073`，本次没有升级节点、Coordinator、sandboxd 或正式 API Server。
- API Server 限额 8 CPU / 1 GiB，客户端限额 4 CPU / 2 GiB。客户端通过集群内 Service 访问，校验入口 TLS 证书。
- 安装 ADX Sandbox SDK 0.1.0 wheel 和 AKernel SDK 0.1.6rc8；三份压力驱动与历史轮次逐字一致，SHA256 保存在 `driver-identity.json`。本次没有重新构建或上传镜像。
- 复合负载使用固定 SWR OCI 制品 `e2e-oci@sha256:44ff437bba879d4941b710a369a8f19266aea34b29002807f0c487fabc9eec9b`。

历史数据来自 AKernel 的 `out/e2e/cn4-sdk-pressure-20261009/`；本次复制成 `baseline.json` 保留。不同轮次的集群瞬时负载可能不同，以下比较用于确认功能修复与同负载表现，不是隔离硬件的性能归因实验。

|---|---:|---:|---:|---:|---:|---:|
| C1 | 592 / 0 | 595 / 0 | 4.93 | 4.95 | 300 | 300 |
| C16 | 6,122 / 0 | 6,192 / 0 | 50.90 | 51.48 | 500 | 500 |
| C64 | 3,286 / 68,066 | 12,913 / 0 | 27.37 | 107.09 | 2,000 | 1,000 |

原 C64 失败是累计达到 10,000 条创建重放记录后拒绝新建，原有效吞吐包含这次错误造成的停顿，不能把新旧吞吐比值当作执行后端提速倍数。本次前三档在约 361 秒内完成 19,700 次创建，超过 10,000 条容量，且尚未到达 600 秒 TTL；没有缓存满拒绝。各阶段客户端在途拒绝、错过发送时间及 create / command / delete 错误均为零。

负载为 8 个常驻 Sandbox，每个以 0.2 秒间隔执行常驻操作；同时以 10 次/秒创建、命令、删除，客户端流转在途上限 16，运行 180 秒，请求 CPU 500 millicores、内存 512 MiB。

## 七类复合负载

每种 profile 运行 120 秒，目标合计 10 个逻辑事务/秒。

| 类别 | interactive 比例 | io-heavy 比例 | churn-heavy 比例 | 客户端在途上限 |
|---|---:|---:|---:|---:|
| command | 30% | 15% | 20% | 4 |
| HTTP | 20% | 15% | 15% | 4 |
| file | 15% | 30% | 10% | 2 |
| lifecycle | 15% | 10% | 35% | 2 |
| PTY | 10% | 10% | 5% | 2 |
| tunnel | 5% | 5% | 5% | 1 |
| checkpoint | 5% | 15% | 10% | 1 |

checkpoint 事务包含 guest Unix Socket 发起 checkpoint、修改文件、reload 和恢复后内容校验；其耗时包含完整恢复闭环。各类沿用原驱动在途限制，不能将客户端未提交的事务算作服务端失败，也不能因为已提交请求全成功就认为目标速率全部达成。

各类执行失败均为零，下面的拒绝是客户端 `rejected_inflight`，表示未向服务端提交。`missed_deadline` 和清理错误均为零。

PTY 共完成 300 次，拒绝数从 236 降到零；原事务均值约 10.27 秒，本次为 266.83 / 267.98 / 266.75 ms，原 P99 桶上界均为 12 秒，本次为 400 / 300 / 400 ms。这里测的是整个 PTY 用例，不是单独 `close()` 耗时。

checkpoint 共成功 73 次，客户端拒绝仍为 288 次；本次三种 profile 的完整 checkpoint 事务均值为 3,778.24 / 4,684.21 / 4,435.57 ms。在原单路在途限制和原到达速率下，三种复合负载都未达到合计 10 事务/秒。驱动 JSON 的 `status=passed` 只说明已提交事务与清理成功，不能当作目标负载达标。

churn-heavy 生命周期 P99 桶上界由原 400 ms 上涨到本次 1,000 ms，均值由 208.22 ms 到 216.97 ms，最大值 1,114.05 ms。本次没有逐事务 Trace，因此仅记录此尾延迟差异，不能从聚合结果确定原因。

## 证据与清理

证据目录：`out/ci/cn4-pressure-regression-20261009/`。`regression.log` 保存执行日志；`campaign-identity.json`、`operation-binary.sha256` 保存制品身份；`baseline.json`、`driver-identity.json` 保存原结果与驱动校验值。

七阶段均正常退出；总计 30,343 次已提交逻辑事务成功，执行失败为零，另有 288 次 checkpoint 客户端在途拒绝。各阶段前后以及最终 Redis `states={}`、`held_ids=[]`、`failed_held_ids=[]`。

最终四个节点均 Ready、重启次数为零，逐节点执行 `sbox list` 确认实际后端数均为零。独立测试 Deployment、Service、ConfigMap 和客户端 Pod 已删除；正式部署版本保持不变。

详细结果位于 `results/`：7 份负载 JSON、每阶段脱敏日志、前后 Redis 审计及 `campaign.json`。`comparison.json` 汇总历史与本次结果，`redis-final.json`、`backend-final.json`、`cleanup-final.json` 保存最终审计。API Server 与节点镜像身份边界见上文；本次不含 Firecracker、Kata 或真实 GPU/NPU 压力证据。
