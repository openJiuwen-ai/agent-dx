# AFS读写专项与缓存合同：验证记录

这批改动把本地读写专项与可复用测量负载接入现有 `afs/tests/run.py`，并把缓存用例拆清为
版本冲突回退、无冲突同版本缓存复用、热缓存权限三项独立检查。产品代码和语义没有修改。
使用、扩展和当前集合以[组件测试入口](../../afs/tests/README.md)为准；性能资产见[工具说明](../../afs/tests/tools/README.md)。

## 实现范围

- 写专项10项：单机与namespace各5项，覆盖跨句柄顺序、同步/追加/关闭、有界接纳推进、必需副本恢复和失败关闭退役。
- 读专项10项：两种拓扑各5项，覆盖三种CRC模式下的范围/EOF、direct预取释放、cached复读内容和预取门控。
- 基础集合由20增至22：版本冲突检查保留原ID，独立增加同版本重开缓存复用、热缓存权限检查。
- 共用typed DFS profile、辅助进程生命周期、退出/清理记录；只在三个缓存case开启现有Info日志。
- 顺序读/写测量资产各一个，显式opt-in；默认run/check-env阻止隐式测量，结果标记性能准入未评估。

## 缓存断言的实际证据

功能数据量16MiB，没有用它形成吞吐或延迟比较：

| 场景 | 观察 | 必须满足的要求 |
| --- | --- | --- |
| H1仍读V1时打开V2 | H1 cached=true；H2/H3 cached=false、keep_cache=false、versioned_read=true；应用未请求O_DIRECT | 明确检查direct回退及V2内容、长度、SHA、EOF，保留原legacy路径未缓存尾部检查，不扩展旧fd一致性承诺 |
| 无版本冲突的同版本复用 | 同fd复读和关闭重开READ均4096→4096；重开cached=true、keep_cache=true；预热后/打开后未读/读完均4096/4096页驻留 | **零新增FUSE READ**，未改成允许少量请求；意外direct、未keep、OPEN丢页或额外READ均失败 |
| 热缓存权限 | 预热4096/4096页；mode000后新open得到13/EACCES；恢复后内容/SHA/EOF正确 | 独立出结果；不要求已打开fd即时撤销 |

实际缓存选择来自产品现有Info事件，驻留由对本UID所有文件的非触碰MAP_PRIVATE映射调用Linux mincore观测。
计数期间只临时关闭自有B挂载的BDI预读，并在finally恢复16384KiB；未改全局系统或源盘。
旧用例的22→41失败记录保留：旧版本句柄还存活时，不能据“另一个句柄读过V2”就断言页缓存已经预热。
修正后在独立、获准缓存且实际全驻留的场景继续保留严格零READ要求。
